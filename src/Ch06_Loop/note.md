# ./test_p85/t3_num.c 实现笔记

- 本题来源 K.N Ch06 章末编程题（分数约分）
- 综合运用了函数封装、指针传参、VLA 数组、snprintf、goto 控制流
- 踩坑极多，是 Ch06 复杂度最高的一道题

## 错误记录

- `calcFractionDigits` 函数里 `do-while` 条件写成 `while(t1 > 0)`，导致**死循环**
  - 计数器从 0 开始，第一次循环后变 1，1 > 0 永远为真
  - 应该检查 `a > 0`，判断"被操作的数什么时候变 0"而不是"计数器本身"
  - **这是第三次踩同一个坑了，必须形成肌肉记忆**

- 辗转相除取 GCD 时，循环结束取了 `temp1` 当 GCD，实际应该是 `temp2`
  - 无论分子>分母还是分母>分子，循环结束时 `b`（即 `temp2`）才是余数归零前的值 = GCD
  - 取反导致 `6/12` 输出 `0/1`，`12/8` 输出 `1/1`

- `scanf` 匹配失败后没有调 `clear()`，导致**输入死循环**
  - 错误输入留在缓冲区，下次 `scanf` 又失败，无限重试
  - 定义了 `clear()` 函数但忘了调用，属于"写了不用"

- 数组定义在 `if` 块内部，用 `goto end` 跳出后数组已销毁，属于**作用域越界**
  - 解决：把数组提到 `main` 顶层定义，整个函数内都有效

- `else if(num2 == 0)` 分支是**死代码**
  - 因为 `checkNum` 已经把 `num2 <= 0` 拦住了，永远走不到这里

- 辗转相除过程中**覆盖了原始 `num1/num2` 的值**，最后约分用的是被改过的值
  - 解决：用 `temp1/temp2` 副本做运算，最后用 GCD 去除原始值

- `snprintf` 第二个参数是**字节数上限（含 `\0`）**，不是数字位数
  - 之前一直混淆这两个概念

- 输入重试用 `goto check` 而非 `for+continue`，结构更清晰
  - 但 `goto` 跳出块后不能访问块内定义的数组——这是用 `goto` 时必须注意的

## 关键认知

- 约分后的位数一定 ≤ 原位数，所以数组大小用原位数算或给固定 32 都安全
- `int` 最大 10 位，分数字符串物理上限是 22 字节（`10 + / + 10 + \0`），32 不可能越界
- 欧几里得算法**不需要 a > b 的前提**，第一步 `a%b=a` 自动等价于交换
